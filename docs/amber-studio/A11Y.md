# Amber Studio: accessibility checklist (WCAG 2.2 AA)

Owner: `a11y-pass`. Foundation lives in `web/src/lib/a11y/`, `web/src/routes/+layout.svelte`, `web/src/routes/layout.css`. Every item below is written to be testable by hand or by `npm run a11y`. Items marked **[auto]** are covered by `web/scripts/a11y-audit.mjs`.

## 0. Foundation (already provided, use it, do not reimplement)

| Piece | Where | Use |
| --- | --- | --- |
| Skip link | `SkipLink.svelte`, mounted in `+layout.svelte`, target `#content` | First Tab stop on every page. Do not render another one. |
| Landmarks | layout wraps pages in `#content` (not a landmark) | **Each page renders exactly one `<main>`**, plus `<header>`/`<nav aria-label>`/`<footer>` as needed. Two navs need distinct labels. |
| Focus ring | `:focus-visible` in `layout.css`, tokens `--ring`, `--focus-ring-width`, `--focus-ring-offset` | Never `outline: none` without a replacement. On dark surfaces add class `on-dark`. |
| Reduced motion (CSS) | `@media (prefers-reduced-motion: reduce)` in `layout.css` | Collapses CSS animation and transition. Opt a truly essential animation back in with `data-motion="essential"`. |
| Reduced motion (JS) | `import { reducedMotion, prefersReducedMotion, motionDuration } from '#lib/a11y/index.ts'` | `$reducedMotion` is a store; gate GSAP, Matter.js, rAF loops, video autoplay. |
| Announcer | `announce(msg, 'polite' \| 'assertive')` | State changes with no visible text change (physics on/off, dock item focus result). Route changes are announced by the layout. |
| Contrast tokens | `contrast.ts`, `npm run a11y:contrast` | Fails if `layout.css` palette drifts from the table below or a pair drops under threshold. |
| Target tokens | `--target-min: 24px`, `--target-comfort: 44px` | `min-h-[var(--target-comfort)]` on touch controls. |

### Grey board palette contrast (checked by `npm run a11y:contrast`)

| Pair | Ratio | Needs |
| --- | --- | --- |
| foreground on board grey `oklch(.93)` | 16.0 | 4.5 |
| card text on white card | 19.7 | 4.5 |
| primary-foreground on primary | 17.8 | 4.5 |
| muted-foreground `oklch(.45)` on board grey / card / muted | 6.1 / 7.4 / 6.6 | 4.5 |
| focus ring `oklch(.4)` on board grey / card | 7.5 / 9.2 | 3 (1.4.11) |

Rules: do not put text lighter than `muted-foreground` on the grey board; never use `--border` (1.17:1) as the only cue that a control exists (give controls a visible label or fill). Text over photos/hero images needs a scrim and a manual check at 4.5:1 (large text 3:1).

## 1. Intro film

- [ ] A visible **Skip intro** button is the first focusable element inside the intro, reachable with one Tab from the page start (after the skip link) and activatable with Enter and Space. Name: "Skip intro".
- [ ] `Esc` also skips. Skipping moves focus to the page's `<h1>` or `<main>` (`tabindex="-1"`), never to `<body>`.
- [ ] With `prefers-reduced-motion: reduce` the intro does **not** play: show the final static frame or go straight to the home page. No flash, no parallax, no autoplaying video. **[auto]** warns if `[data-intro]` is still visible after settling under reduce.
- [ ] No content flashes more than 3 times per second, and there are no large high-contrast flashes (2.3.1).
- [ ] Anything longer than 5 s that moves has a pause/skip control (2.2.2). Intro total length stated in the control's `aria-description` if over 5 s.
- [ ] Intro container is `role="dialog"`/`aria-modal` only if it truly blocks the page; if so, trap focus inside, restore focus on close. If it merely overlays, mark the page behind `inert` while it plays, and remove `inert` when it ends. Focus never lands on something invisible. **[auto]** fails on focus inside `aria-hidden`.
- [ ] Decorative layers are `aria-hidden="true"`; any spoken content (title card text) exists in the DOM as real text, in reading order.
- [ ] Intro seen once per session is remembered (store), so returning keyboard users are not forced through it again.
- [ ] Skipping or finishing calls `announce('Intro finished')` (polite).

## 2. Board (homepage collage and work grid)

- [ ] DOM order is reading order. CSS `order`/absolute positioning must not reorder focus: tab through the page, the sequence must match the visual left-to-right, top-to-bottom order (2.4.3, 1.3.2). Collage items are in the same sequence as the mobile single column.
- [ ] Each card is **one** focus stop: a single `<a>` (or `<button>`) whose accessible name is the project/title, e.g. "NeedBe Foundation, menstrual-health education". No card with an `<a>` wrapping another `<a>`, no duplicate links to the same URL in one card. **[auto]** fails on focusables with no accessible name.
- [ ] Card is an `<article>` or list item inside a `<ul>`/`<ol>` with `aria-label="Selected work"`, so screen readers announce "list, 6 items". Not a `div` soup, not `role="grid"` (it is not a data grid).
- [ ] Every image has meaningful `alt` describing the work, or `alt=""` if it duplicates the card text. Favicon-on-grey placeholder tiles use `alt=""` and carry the title as text.
- [ ] Hero plate (16:9): one `<h1>`/`<h2>` in correct outline order; heading levels do not skip. One `<h1>` per page. **[auto]**
- [ ] Hover-only information (tooltips, captions) is also available on focus and on touch (1.4.13): dismissible with `Esc`, hoverable, persistent.
- [ ] Card hit area is the whole card; minimum 44x44 CSS px on touch, never under 24x24 (2.5.8). Gap between adjacent targets is >= 8px on mobile.
- [ ] **Mobile order**: collage is dropped, work tiles are a single column in the same order as the desktop DOM; nothing is `display:none` on mobile yet focusable. Verify at 390 px and at 320 px width (1.4.10 reflow): no horizontal scroll, no clipped text. **[auto]** runs 390 px.
- [ ] Text zoom to 200% and browser zoom to 400%: content remains usable; no `user-scalable=no` / `maximum-scale=1`. **[auto]**
- [ ] Orientation not locked (1.3.4). Text spacing override (line-height 1.5, letter 0.12em, word 0.16em, paragraph 2em) does not clip card titles: use `min-height`, not fixed `height`, on text containers.
- [ ] Parallax/stagger-in motion honours `$reducedMotion` (elements simply appear).
- [ ] `<html lang="en">` is set (app.html) and any non-English phrase carries `lang`. **[auto]**

## 3. Physics (gravity / scatter, Matter.js)

- [ ] Physics is **opt-in and off by default** under `prefers-reduced-motion: reduce`, and the toggle is shown but starts off. **[auto]** fails if `[data-physics-toggle][aria-pressed=true]` under reduce.
- [ ] Toggle is a real `<button>` (or `role="switch"`) with `aria-pressed`/`aria-checked`, visible text label ("Gravity: on/off"), operable with Enter and Space, and reachable by Tab. Expose `data-physics-toggle` on it. **[auto]** checks element type, state attribute, and Space operability.
- [ ] A separate **Pause/Resume** control exists for the running simulation (2.2.2), exposed as `data-physics-pause`, also keyboard operable. Physics that runs > 5 s needs it. **[auto]** warns on physics routes without it.
- [ ] Toggling calls `announce('Gravity on. Cards are falling. Press Pause to stop.')` / `announce('Gravity off. Cards restored.')`.
- [ ] **Non-physics fallback**: with physics off (or unsupported, or reduced motion) every card sits in the normal grid, in normal DOM order, fully usable with keyboard and screen reader. Physics is progressive enhancement only.
- [ ] While physics runs, card **DOM order, focusability and accessible names do not change**; only a transform changes. Tabbing to a falling card must still work: the focused card scrolls into view and is not covered (2.4.11); focus ring is not clipped by the canvas.
- [ ] Nothing is only reachable by drag. Drag/throw gestures have a single-pointer alternative: click or keyboard activation opens the card (2.5.1, 2.5.7 dragging movements).
- [ ] Physics canvas, if used, is `aria-hidden="true"` and never contains the only copy of content. Pointer capture does not block page scrolling on touch (`touch-action: pan-y` unless actively dragging).
- [ ] Rendering loop stops when the tab is hidden, the control is toggled off, or `$reducedMotion` flips to true mid-session (listen to the store).
- [ ] No flashing/strobing from collisions (2.3.1).

## 4. Dock (nav) and mobile dock

- [ ] `<nav aria-label="Primary">` containing a list; dock is not `role="menu"` (that role implies application-menu behaviour); use links/buttons.
- [ ] **Roving tabindex**: dock is a single Tab stop. Arrow Left/Right (Up/Down if vertical) move focus between items, `Home`/`End` jump to first/last, `Tab` leaves the dock. Exactly one item has `tabindex="0"`, the rest `-1`. Focus wraps or stops consistently (document which).
- [ ] Each item has an accessible name that matches its visible label (2.5.3 label in name): "Work", "Reel", "About", "Talk", "Terminal", "Games". Icon-only items get `aria-label`; the icon is `aria-hidden`.
- [ ] Current page item has `aria-current="page"`. Items that open something use `<button>` with `aria-haspopup`/`aria-expanded` as appropriate; items that navigate use `<a href>`.
- [ ] Magnify/hover scale effect is mirrored on `:focus-visible`; with reduced motion, magnify is disabled (or 0 ms) but labels remain. Labels shown on hover are also shown on focus (1.4.13) and are not the only name source.
- [ ] Targets: >= 44x44 CSS px on mobile dock, >= 24x24 always, even when un-magnified. Spacing prevents mis-taps. **[auto]** warns below 24px.
- [ ] Mobile dock stays inside safe-area insets, does not cover the focused element (2.4.11 Focus Not Obscured): `scroll-padding-bottom` >= dock height on `html`.
- [ ] `Esc` closes any dock popover and returns focus to its trigger.
- [ ] ⌘K / Ctrl+K palette (when added): `role="dialog"` + `combobox` pattern, label, focus trap, restores focus, results announced via `announce('N results')`. Not reachable only by shortcut: a visible button exists (2.1.1, 3.2.6 consistent help).
- [ ] Shortcut keys with single characters are avoidable or remappable (2.1.4).

## 6. Running the audit

```sh
cd web
npm install
npm run build
npm run a11y                       # starts vite preview on :4173, audits, exits non-zero on failures
npm run a11y:contrast              # palette check only, no browser

A11Y_BASE_URL=http://localhost:5173 npm run a11y          # against a running dev server
node scripts/a11y-audit.mjs --routes=/,/physics-demo --json=/tmp/a11y.json
node scripts/a11y-audit.mjs --tabs=100 --settle=4000      # longer tab walk / intro settle time
```

Env: `A11Y_CHROMIUM` overrides the browser binary (defaults to `/opt/pw-browsers/chromium` when present, otherwise Playwright's own). Routes returning 404 are skipped unless passed with `--routes`, so `/physics-demo` and `/dock-demo` are optional until they exist.

Matrix: every route x {desktop 1280x800, mobile 390x844 touch} x {no-preference, reduce}. Failures: axe WCAG violations, missing lang/title/`<main>`/`<h1>`, positive tabindex, first Tab stop not the skip link, focusable without name, no focus indicator, focus inside `aria-hidden`, tab trap, infinite animations under reduce, physics on by default under reduce, toggle not button/switch. Warnings (non-failing): axe best-practice items, extra `<h1>`, off-screen focus, targets < 24 px, missing pause control, lingering intro under reduce.

Hooks other workers should expose so the audit can see them: `data-intro` (intro root), `data-physics-toggle`, `data-physics-pause`.
